# リアルタイム受信と履歴表示

USBでNMEAを受信し、ブラウザーで現在位置と軌跡を確認します。
計測ごとに元ログと座標を保存し、停止後や再起動後にも履歴を選べます。
WindowsとmacOS共通のPythonコードです。

## 起動

リポジトリを更新し、`pyproject.toml` のあるフォルダーで実行します。
Gitで取得した場合の更新方法は `git pull --ff-only` です。
ZIPの場合は最新版を別フォルダーに展開し、必要なら以前の `data/live/` を移します。

```sh
uv sync --locked
uv run python -m gnss_maps.live
```

ブラウザーが自動で開きます。
開かない場合は、同じPCで <http://127.0.0.1:8765> にアクセスします。
終了するには、画面で計測を停止してからターミナルで Ctrl+C を押します。
ブラウザーのタブを閉じても、Pythonが動いていれば記録は続きます。

## 画面からログを一括インポートする

1. 「ログを読み込む」で `.log`・`.txt`・`.nmea` ファイルを選びます。
2. 「一括インポート」を押します。
3. 完了すると履歴が選択され、地図・各タブ・シークバーで確認できます。

NMEAテキストを50 MiBまで読み込めます。元ファイルは変更せず、元データのコピーと解析済み座標を保存します。実測時刻の間隔を待たずに一括処理します。読み込み中もUSBの受信・記録は継続します。
有効なGGA位置がないファイルはエラーになり、履歴へ登録しません。
ファイルは同じPCのPythonサーバーへ送られ、外部サービスへは送信しません。
日時はログ内のRMCとGGAから取得します。履歴の登録時刻はインポートしたPC時刻です。

## 機器なしで試す

接続先の「デモ（架空の位置）」を選び、「計測開始」を押します。
架空の軌跡と、品質5、4、0の変化を表示します。
デモは約5分で終了します。
履歴には「デモ」と明記し、実測と区別します。

保存済みのNMEAログも、受信するように再生できます。

```sh
uv run python -m gnss_maps.live --replay "data/measurement.txt"
```

画面の接続先で「指定したログを再生」を選びます。
GGAごとに0.2秒待つ方式なので、元ログの空白時間を再現する再生ではありません。
履歴には「ログ再生」と表示します。

## USBから計測する

1. 受信機をデータ通信対応USBケーブルでつなぎます。
2. Tera Termやu-centerなど、同じポートを開いているソフトを切断します。
3. 「ポート一覧を更新」を押します。
4. Windowsなら `COM3` など、Macなら `/dev/cu.usbmodem...` や `/dev/cu.usbserial...` を選びます。番号や名前は実機で異なります。
5. 通信速度を選び、計測名を入力して「計測開始」を押します。
6. 終了したら「停止して保存」を押します。

通信条件は8ビット、パリティなし、ストップ1、フロー制御なしです。
通信速度の初期値は38400ですが、USB-UART経由の場合は機器の設定と合わせます。
GNSS USB直結の場合には、この速度指定が実際のデータ転送速度を決めないことがあります。
機器やOSによってはUSBドライバーが必要です。
プログラムは測位設定やWi-Fi設定を変更せず、受信データを読み取ります。
シリアルポートを開くと制御線の状態が変わり、基板によっては再起動する可能性があります。

補正データの取得は、既存のESP32側の動作を想定しています。
このPythonプログラムにはNTRIPクライアント機能はありません。

## オフライン地図と表示タブ

国土地理院の地図描画には同梱したLeaflet 1.9.4を使用します。
国土地理院の地図はAPIキー不要です。
Google航空写真は後述の別設定が必要です。
地図、JavaScript、CSS、IBM Plexフォントはローカルから読み込みます。

保存済みの地図は次の場所から読み込みます（起動したフォルダーが基準です）。

- `data/desktop/presets/std.mbtiles`：地形図
- `data/desktop/presets/seamlessphoto.mbtiles`：航空写真

履歴を選び、地図の「全経路の地図を準備（ネット必要）」で取得できます。
初回取得後はページを再読み込みし、履歴を選び直してください。
任意のMBTilesを使う場合は [デスクトップ版の手順](DESKTOP.md) を参照してください。
保存範囲外や未取得の場所は背景が表示されません。経路は表示できます。
保存済み画像より高倍率に拡大しても、画像自体の詳細は増えません。
画面内の「この点をGoogleマップで開く」はオンラインの外部リンクです。

| タブ | 内容 |
| --- | --- |
| 地図 | 地形図・航空写真に品質別の軌跡を表示。拡大縮小・移動が可能 |
| 散布図 | 最初の有効点を原点とした東西・南北の変位（概算m）。真値に対する誤差ではない |
| 時系列 | 品質・衛星数・HDOPを経過時間で表示。グラフをクリックして時点を選択 |
| 生データ | 元ログを行番号付きで表示。GGA/RMC/チェックサム不正などを絞り込み可能 |

タブを切り替えても受信・保存は続きます。選択した履歴とスライダーの時点は共有します。
生データの一時停止は表示だけに作用します。表示は最大1,000行です。
履歴の生データは選択点のUTCに最初に一致するGGAまでを表示するため、
複数日で同じUTCが繰り返されるログには現時点で制限があります。
時系列は有効な測位点が対象であり、測位不能（品質0）は生データで確認します。
左右矢印キーでもタブを切り替えられます。

## 画面の見方

- 「受信中」と測位品質を画面上部に表示します。
- 有効なGGAが3秒以上更新されないと、現在位置のマーカーを非表示にします。
- 測位不可のGGAを受け取った場合も、現在位置としては表示しません。
- その際、過去の軌跡は残し、座標欄には「最後の有効位置」と表示します。
- 品質1は灰色、2は橙色、5は紫色、4は緑色です。
- 無効なGGA、時刻の逆転や重複、2秒を超える測定時刻差で線を分けます。
- 地図では「最新位置を追う」を有効にすると地図が移動します。
- 航空写真とのずれは、GNSSの真値に対する誤差そのものではありません。

「保存した履歴」から計測を選ぶと、その軌跡を表示します。
スライダーで測定点を選び、その点までの軌跡、座標、測位品質、日時を確認できます。
「履歴を再生」は1点につき0.2秒で表示を進めます。
時刻の空白を待つ実時間再生ではありません。
「全軌跡・最後の点」で末尾に戻ります。
日時はRMCとGGAの時刻が一致した場合に日本時間で表示し、日付が取得できなければUTC時刻と「日付不明」を表示します。
ブラウザーの時計やGPS位置は、GNSSの測定値として使用しません。

## 保存先と書き出し

既定では次の場所に保存します。

```text
data/live/
├── history.sqlite3      # 計測一覧と位置データ
├── history.sqlite3-wal  # SQLiteの動作中に作られることがある管理ファイル
├── history.sqlite3-shm  # 同上
└── <計測ID>.log         # 受信した元データ
```

元データは受信するたびにファイルへ書き出し、座標はSQLiteへ逐次保存します。
通常の停止後も履歴を残します。
異常終了した記録は、次の起動時に `interrupted` と表示します。
保存フォルダーをコピーする場合は、先にPythonを終了してください。
停電やOS障害による最後のデータの消失まで保証するものではありません。

画面からCSV、KML、元ログをダウンロードできます。
CSVの `measured` はRMCと対応付けたUTC日時、`received` はPCが解析した時刻です。
ログ再生時の `received` は再生した時刻であり、元の測定時刻ではありません。
KML書き出しは区間ごとの軌跡です。
日時付きピンが必要なら、元ログを従来の変換コマンドで処理します。

```sh
uv run python -m gnss_maps "data/live/<計測ID>.log" --out result
```

保存先と待ち受けポートは変更できます。

```sh
uv run python -m gnss_maps.live --data-dir data/field-test --port 8766
```

サーバーは自分のPCの `127.0.0.1` のみに接続を受け付けます。
スマートフォンなど別機器からのアクセスには対応していません。
`data/` はGitの管理対象外です。
履歴は全点を読み込みます。長いログは読み込み時間とメモリー使用量が増えます。保存する実験区間と草刈り幅KMLは最大50,000点です。

## 現時点の検証範囲

- 自動テストで、USB受信の分割行、切断、日付の対応付け、測位不可、古い位置の扱い、保存、HTTP操作を検証。
- Macのブラウザーで架空データによる受信、停止、履歴表示を確認。
- 実機のUSB受信とWindows実機は未検証。
- オフライン地図には対象範囲のMBTilesが必要です。Google航空写真にはAPIキーとPCのネット接続が必要です。

### 経路の途中で地図が途切れる場合

履歴を選び、地図の「全経路の地図を準備（ネット必要）」を押してください。経路全体と周囲の余白を国土地理院から取得し、標準プリセットを置き換えます。対象範囲が配信元に伝わります。範囲が広すぎる場合は取得を中止してエラーを表示します。詳細画像がない場所は、保存済みの粗い画像があれば拡大して補います。どの倍率にも画像がない場所は空欄です。

### 草刈りの仮幅推定モード

地図タブのチェックをONにすると直径50 cmの回転刃の推定通過範囲を表示します。初期状態は北向き・前進です。走行中のカーブでは機体方位を更新し、折り返しでは前進・後退を切り替えます。その場旋回はしない前提です。

直前の判定位置から20 cm以上移動したとき、移動方向を求めます。前進中は移動方向、後退中はその逆を機体方位の候補とし、直前の機体方位から120°を超える変化は折り返しと判定します。それ以下はカーブとして更新します。停止付近の細かな揺れと区間の切れ目では方位を保持します。欠測中の旋回や大きな測位誤差は正しく推定できないことがあります。

各点の推定機体前方へ30 cm補正して刃の中心を求め、半径25 cmの円が移動した範囲を表示します。通信切断区間はつなぎません。青点は推定した刃の中心、細い線はアンテナ経路です。時系列の過去の点だけで推定するため、シーク中に将来の位置を参照しません。

画面と統合KMLで同じ推定ルールを使います。直近50,000点より前の推定状態も引き継ぎます。通常のCSV・KML・元ログ・数値表示は元のアンテナ座標です。推定帯は刈り取り実績を保証するものではありません。

### 草刈り幅をGoogleマイマップに表示する

1. 履歴を選択し、草刈りの仮幅推定モードをONにします。初期状態が北向き・前進であることを確認します。
2. シークバーで保存したい時点を選びます。「全軌跡・最後の点」で表示中の全経路を対象にできます。
3. 「草刈り幅KMLを作成（表示時点まで）」を押し、現れた保存リンクからKMLを保存します。
4. Googleマイマップで地図を開き、レイヤーの「インポート」からKMLを選択します。

通常の「KML保存」はアンテナの線、専用ボタンは直径50 cmの刃の推定通過範囲をポリゴンとして出力します。前方30 cm補正・時系列方位推定・切断区間の分離は画面と共通です。重なった帯はShapelyで統合し、品質別の色をまとめて緑色の面として保存します。離れた範囲と内側の未通過部分の穴は保持します。マイマップ側でスタイルが変わる場合はレイヤーのスタイルを調整してください。

作成ボタンを押した時点の表示対象（最大50,000点）のみを保存します。シーク位置や受信データが変わった後は再作成してください。1,000図形ごとの分割は廃止し、統合した図形を1つのKMLに保存します。統合後も5 MBを超える場合はエラーを表示します。シークバーで対象範囲を短くして再作成してください。マイマップには地図全体・レイヤー数等の上限もあるため、大量の記録は地図を分けてください。背景の航空写真はKMLに含みません。Googleアカウントへの自動アップロードは行いません。

Googleの読み込み仕様：[マイマップ公式ヘルプ](https://support.google.com/mymaps/answer/3024836?hl=ja)。実際のGoogleマイマップへのインポートは未検証です。

統合KML機能の更新後は `uv sync` を実行し、サーバーを再起動してください。統合処理はローカルで実行され、インターネット接続は不要です。

## Google航空写真へ切り替える

地図右上で「地形図（国土地理院）」「航空写真（国土地理院）」「航空写真（Google・オンライン）」を選べます。Googleへの切り替えでも、経路・品質別の色・履歴の選択時点・草刈り幅の表示を引き継ぎます。

Google Cloudで請求先を登録し、Maps JavaScript APIを有効にしてブラウザー用APIキーを作成してください。API制限はMaps JavaScript API、ウェブサイト制限は使用するローカルURL（例：`http://127.0.0.1:8766/*`、`http://localhost:8766/*`）に設定します。キーはブラウザーから見える仕様なので、制限を設定し、GitHubには登録しません。

macOSのターミナル：

```sh
export GOOGLE_MAPS_API_KEY='自分のAPIキー'
uv run python -m gnss_maps.live --port 8766
```

Windows PowerShell：

```powershell
$env:GOOGLE_MAPS_API_KEY = '自分のAPIキー'
uv run python -m gnss_maps.live --port 8766
```

Googleを選択した時だけ公式APIを読み込みます。PC自体のインターネット接続が必要です。キー未設定・接続不可・読み込み失敗では説明を表示して既存地図を維持し、オフライン検出時は国土地理院へ戻します。通信の一部だけが遮断された場合、ブラウザーがオフラインと判定しないことがあります。その際は手動で国土地理院に切り替えてください。

Google航空写真のダウンロード・オフライン保存は行いません。「全経路の地図を準備」は国土地理院のみ取得します。GNSSログの保存・インポートは従来どおり使えます。Googleのロゴ・著作権表示は標準表示を維持します。

APIは無料枠を超えると課金されます。公開・配布する際はGoogle Maps Platformの規約に従い、利用規約・プライバシーポリシーを用意してください。

- [Maps JavaScript APIの料金](https://developers.google.com/maps/documentation/javascript/usage-and-billing)
- [利用ポリシー](https://developers.google.com/maps/documentation/javascript/policies)

## 経路の一部分だけを表示する

「表示する時点」のバー直下にある「経路の表示範囲」で、開始・終了のバーを動かしてください。各バーには点番号と日時が表示され、両端を含む区間が地図・散布図・時系列に適用されます。境界を逆転させると、もう一方も同じ点まで移動します。1点だけの表示も可能です。

上のバーで位置を確認してから「表示中の時点を開始にする」「表示中の時点を終了にする」でも指定できます。範囲を変更すると選択区間全体が表示され、履歴再生はその区間内で動作します。「全範囲に戻す」で解除できます。最新位置の追従を有効にする、または別の履歴を選択すると範囲を解除します。

元ログを切り取ったり変更したりする機能ではありません。CSV・KML・元ログの保存と生データ閲覧は従来どおり全ログが対象です。草刈り幅KMLのみ、選択区間の表示時点までを対象とします。長い履歴を区間に分ける場合、保存する区間を50,000点以内に指定してください。

## 実験ごとの受信機の取り付け位置補正

地図タブの「受信機から刃の中心への位置補正」で、前後と左右の水平距離をcm単位で指定します。前方と右方が正、後方と左方が負です。受信機が刃の中心より後ろ40 cm、左20 cmなら「前後40、左右20」を入力します。補正なしは両方0です。高さはこの2D補正には使いません。

既定値は前方30 cm、左右0 cmです。入力範囲は各−1000〜1000 cmで、変更は地図の推定帯、刃の中心マーカー、草刈り幅KMLに反映されます。通常の座標、CSV、経路KML、元ログは変更しません。機体の推定方位に合わせて補正方向が回転します。刃の直径は従来どおり50 cmです。

設定は現在の画面だけで有効です。履歴切り替えやページの再読み込みで既定値へ戻るため、実験の記録に取り付け距離を残してください。草刈り幅KMLの説明にも補正値を記載します。設定変更後はKMLを再作成してください。方位は経路からの推定であり、その場旋回や傾斜による位置変化を正確に補正するものではありません。

## APIキーをPCに保存する

最新版へ更新して `uv sync --locked` を実行してください。
プロジェクトの `.env.example` を `.env` にコピーし、次の形式でキーを保存します。

```text
GOOGLE_MAPS_API_KEY=ここに自分のキー
```

WindowsではプロジェクトのPowerShellで `notepad .env` を実行して編集できます。
ファイル名は `.env.txt` ではなく `.env` にしてください。
次回から通常の起動コマンドだけで読み込みます。設定変更後はサーバーを再起動してください。
保存先は `pyproject.toml` と同じフォルダーです。設定ファイルは暗号化されません。
`.env` と `.env.*` はGit対象外で、空のひな形 `.env.example` のみ共有します。
ターミナルに同名の環境変数が残っている場合はそちらが優先されます。
ZIPで別フォルダーへ更新する際は、自分のPC内で `.env` も移してください。他の人へは渡しません。

## 実験1、実験2として区間を保存する

1. 保存した履歴を開きます。長いログも前半から読み込みますが、点数が多いほど読み込み時間とメモリー使用量が増えます。
2. 「表示する時点」と「前の点／次の点」、または点番号入力で開始点を選び、「表示中の時点を開始にする」を押します。
3. 同様に終了点を指定します。
4. 「区間名」に実験1などを入力し、「区間を新しく保存」を押します。
5. 「保存した実験区間」から選び、「選択した区間を開く」で再表示します。

開始と終了は点IDで保存するため、同時刻の点や日付をまたぐ記録も区別できます。
1つの保存区間は最大50,000点です。元ログを変更せず、履歴DBに範囲を保存します。
再起動後も区間一覧を読み込めます。保存は毎回新規作成で、同名の区間も上書きしません。
保存区間を開いた状態ではライブ受信点を追加せず、元の履歴を選び直すと全体に戻れます。
通常のCSV、KML、元ログボタンは、元履歴全体の未補正データを保存します。

### FIXの外周と走行区間の位置を合わせる

1. 外周の履歴で品質4の点を選び、「現在のFIX点を基準点にする」を押します。
2. 必要なら走行の履歴へ切り替えます。基準点は保持されます。
3. 実験区間を指定し、物理的に同じ場所を計測した品質2の点を選んで「現在の品質2の点を位置合わせ点にする」を押します。
4. 対応点の日時、座標、品質と、「東○m・北○m」の補正量を確認します。負は西と南です。
5. 「選択区間に位置合わせを適用」をONにし、補正前後を比較します。「基準履歴のFIX経路を重ねる」で外周を確認できます。
6. 区間を保存すると、範囲、対応点、補正量、取り付け位置補正も保存します。保存した区間を開くと位置合わせを有効にして復元します。

位置合わせは同一場所の2点の緯度経度差を選択区間に一律加算します。
表示するメートル値は基準緯度のWGS84局所縮尺で換算したものです。
基準の外周と元ログは移動せず、品質2がFIXに変わることもありません。
区間にFIXなど他品質が混ざる場合も、選択区間内は一律に移動します。必要な走行区間だけを切り出してください。
ずれが時間とともに変化する場合、この方法では補正できません。終点など別の同一地点でも比較してください。

取り付け位置補正は機体方位に沿った補正、今回の位置合わせは地図上で固定方向の平行移動で、別々に適用します。
位置合わせした草刈り幅KMLを出す場合は、区間を保存して開いてから専用ボタンを押します。
対応点を変更した場合は新しい区間として保存し直してください。

## 外周FIXと実験の刈り幅を重ねる

画面上部の「外周と実験の重ね合わせ」で、外周FIXの保存区間と、刈り幅を表示する実験の保存区間をそれぞれ選び、「2つの区間を重ねて表示」を押します。実験に保存した取り付け位置補正を復元し、刈り幅推定をONにします。外周は選択した区間のFIX点だけを未補正の線で表示します。測位が途切れた区間やFIX以外の点をまたいで線をつなぎません。

実験もFIXの場合、品質2との位置合わせは不要です。既に位置合わせを保存している実験は、その補正も復元します。「選択区間に位置合わせを適用」で解除できます。

- 「地図」タブ：右上で航空写真を選び、外周と推定帯を重ねて確認します。
- 「平面図（cm目盛り）」タブ：緑の破線が外周FIX、青い面が推定刈り幅、灰色の線がアンテナ経路です。「全体を表示」で両区間を収めます。
- 「1目盛り1 cm」を押すと、中心位置を保って1 cm間隔のグリッドに拡大します。ドラッグで移動、ホイールや＋−で倍率を変更できます。全体表示時の目盛りは見やすい間隔に自動調整します。

平面図は外周の最初の表示点を原点とするWGS84の局所平面近似です。東西と南北の単位はmで、縮尺は同一です。1 cmの目盛りは表示の細かさであり、測位や刈り幅推定の精度が1 cmであることを意味しません。広い地域の測量用投影には対応していません。外周は常に全体、実験は選択時点まで表示します。

2つの区間の組み合わせ自体は保存しません。再起動後は各区間を選び直してください。

## 外周内の塗りつぶし率

外周と実験を重ねた後、「表示時点までの塗りつぶし率を計算」を押します。
開始点からシークバーの選択点までの刈り幅を計算します。計算開始時に再生と最新位置の追従を停止します。
区間、時点、取り付け補正、位置合わせ、外周の閉じ方を変えると結果を無効にし、再計算を促します。

外周の始点と終点が一致しない場合は、「外周の始点と終点を直線で結んで閉じる」を確認して選びます。
閉じる線の距離も結果に表示します。地図と平面図にも閉じる線を表示します。
外周は途切れのないFIXの1区間に限定します。自己交差、面積ゼロ、非FIX点、複数の測位区間がある場合はエラーになります。

計算式：

1. 刃の半径25 cmの推定通過範囲を作り、重複を統合する。
2. 統合した推定範囲と外周ポリゴンの共通部分を求める。
3. 外周内の塗りつぶし面積 = 重複を除いた推定刈り幅面積 − 外周外の面積。
4. 塗りつぶし率（%）= 外周内の塗りつぶし面積 ÷ 外周面積 × 100。
5. 未塗りつぶし面積 = 外周面積 − 外周内の塗りつぶし面積。

画面には数値を代入した式と面積（m²）を表示します。割合は丸め前の面積で計算します。
画面の色やピクセル数ではなく、Shapelyによる図形演算です。面積は外周始点を原点とするWGS84局所平面近似、円弧は多角形近似です。
KML出力と同じ刈り幅の計算を使い、重複や往復は二重に数えません。欠測区間はつなぎません。
これは直径50 cmの刃による推定面積であり、実際に草が刈れた割合を保証しません。外周内の障害物や除外領域は現時点では設定できません。
