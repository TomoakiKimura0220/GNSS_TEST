# GNSS_TEST — GNSS観測ノート

ZED-F9Pなどの受信機が出力するNMEAデータをUSBで読み取り、位置と移動履歴を表示するPythonプロジェクトです。生データの保存、履歴の再生、CSV・KML出力に対応しています。

macOS／Windows向けです。ブラウザー版では、保存済みの地形図・航空写真を使い、PCがオフラインでも地図を表示できます。国土地理院の地図はAPIキー不要です。
Google航空写真も選べますが、利用者自身のAPIキーとPCのインターネット接続が必要です。

初めて使う場合は「導入と起動」から「計測と生データの保存」まで進めてください。履歴、地図、ファイル構造は必要なときに参照できます。

## 機器とデータの流れ

```text
GNSS衛星 → アンテナ → ZED-F9P（測位計算）
                          ↑ 補正データ
基準局 → インターネット → モバイルルーター → ESP32

ZED-F9Pの測位結果 → USBシリアル → PCのPythonアプリ
                                  ├─ 生データを.logに保存
                                  ├─ 座標と履歴をSQLiteに保存
                                  └─ ブラウザーに地図・グラフを表示
```

ESP32側の補正データ受信は、貸与された機器の設定を利用する想定です。このアプリからNTRIP接続や受信機の設定変更は行いません。PCの地図表示と、ESP32が使うモバイル通信は別です。

## 導入と起動

### 必要なもの

- macOSまたはWindowsのPCとブラウザー
- 初回のPython環境構築と地図取得に使うインターネット接続
- 実測する場合だけ、NMEAを出力するGNSS受信機とデータ通信対応USBケーブル

機器やGoogleアカウントがなくてもデモを試せます。
ブラウザー版ではNode.jsやTkinterの追加設定は不要です。
Windows実機は未検証のため、引き継ぎ先でもデモによる動作確認を行ってください。

### 1. uvをインストールする

macOSでは「ターミナル」で実行します。

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windowsでは「PowerShell」で実行します。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

どちらも[uv公式のインストール方法](https://docs.astral.sh/uv/getting-started/installation/)です。
完了後にターミナルを開き直し、`uv --version` でバージョンが表示されることを確認します。
Pythonは次の手順でuvが用意するため、先に別途インストールする必要はありません。

### 2. プログラムを取得する

[GitHubのページ](https://github.com/TomoakiKimura0220/GNSS_TEST)で「Code → Download ZIP」を選び、ZIPを展開してください。
展開した `GNSS_TEST-main` の中に `pyproject.toml` があることを確認します。

- Windows：そのフォルダーをエクスプローラーで開き、アドレス欄に `powershell` と入力してEnterを押します。
- macOS：ターミナルに `cd `（末尾に半角スペース）まで入力し、展開したフォルダーをドラッグしてEnterを押します。

Gitを導入済みの場合は、ZIPの代わりに次の方法でも取得できます。

```sh
git clone https://github.com/TomoakiKimura0220/GNSS_TEST.git
cd GNSS_TEST
```

### 3. 環境を用意して起動する

`pyproject.toml` のあるフォルダーで、1行ずつ実行します。
macOSとWindowsで共通です。

```sh
uv python install 3.12
uv sync --locked
uv run python -m gnss_maps.live
```

ブラウザーに「GNSS 観測ノート」が表示されれば起動成功です。
自動で開かなければ、同じPCで <http://127.0.0.1:8765/> を開きます。
ターミナルはアプリを使い終わるまで閉じないでください。

**初回は地図の背景がなくても正常です。**
地図画像と計測ログはGitHubに含めていません。
まずデモで受信と保存を確認し、その後に「オフライン地図を準備する」へ進みます。

### 2回目以降の起動と更新

同じプロジェクトのフォルダーで `uv run python -m gnss_maps.live` を実行します。
取得済みの国土地理院地図はオフラインでも使えます。

Gitで取得した場合は、計測とアプリを停止してから更新します。

```sh
git pull --ff-only
uv sync --locked
uv run python -m gnss_maps.live
```

更新時にローカル変更のエラーが出たら、変更を消さずに管理者へ相談してください。
ZIPの場合は最新版を別フォルダーへ展開し、アプリ停止後に以前の `data/` を移します。
`.venv/` はコピーせず、新しいフォルダーで `uv sync --locked` を実行します。

### 機器なしで試す

1. 接続先で「デモ（架空の位置）」を選びます。
2. 「計測開始」を押します。
3. 地図・散布図・時系列・生データのタブを切り替えます。
4. 「停止して保存」を押し、履歴のスライダーを動かします。

デモの位置は架空です。保存した地図の範囲外では背景が表示されません。

## 計測と生データの保存

1. 受信機をデータ通信対応USBケーブルでPCにつなぎます。
2. Tera Termなど、同じシリアルポートを使うソフトを閉じます。
3. 「ポート一覧を更新」を押し、Windowsなら `COM3`、Macなら `/dev/cu.usbmodem...` など、実際に表示された接続先を選びます。
4. 通信速度を機器の設定に合わせます。画面の初期値は38400です。
5. 計測名を入力し、「計測開始」を押します。
6. 終わったら「停止して保存」を押します。

**「計測開始」と同時に、生データの自動保存も始まります。**
受信したバイト列を `.log` に保存するため、表示フィルターで隠した行や解析できない行も記録に残ります。タブの切り替えや生データの「表示を一時停止」は記録に影響しません。

保存した履歴を選び、「元ログ保存」でログを取り出せます。「CSV保存」「KML保存」では解析済みの座標を書き出します。

```text
data/live/
├── history.sqlite3     # 計測一覧・座標・日時・測位品質
└── <計測ID>.log        # シリアル通信で受け取った生データ
```

ここでいう生データは受信機から出力されたNMEAなどです。衛星の観測値や搬送波データが出力されていなければ、それらを記録することはできません。

終了するときは計測を停止し、ターミナルで `Ctrl+C` を押します。ブラウザーを閉じただけではPythonの受信・記録は終了しません。バックアップするときはPythonを終了してから `data/live/` 全体をコピーしてください。

## 4つの表示タブ

| タブ | 表示・操作 |
| --- | --- |
| 地図 | 品質別の軌跡、地形図／航空写真の切り替え、拡大縮小、最新位置の追従 |
| 散布図 | 選択区間の最初の有効位置を原点とした東西・南北の変位。単位は概算m |
| 時系列 | 測位品質・使用衛星数・HDOP。グラフのクリックで時点を選択 |
| 生データ | 元ログの行番号とNMEA原文。GGA／RMCなどの絞り込み、表示の一時停止 |

選択した履歴と表示時点はタブ間で共有します。散布図は最初の位置からの変位であり、真値に対する誤差ではありません。

| GGAの品質 | 意味 | 色 |
| --- | --- | --- |
| 0 | 測位不可。位置として採用しない | — |
| 1 | 単独測位 | 灰 |
| 2 | 差分補正 | 橙 |
| 4 | RTK FIX（整数解） | 緑 |
| 5 | RTK FLOAT（実数解） | 紫 |

FIXになったことと、実際の位置誤差を確認したことは別です。精度評価には既知の基準位置などとの比較が必要です。

## 画面からログを一括インポートする

1. 「ログを読み込む」で `.log`・`.txt`・`.nmea` ファイルを選びます。
2. 「一括インポート」を押します。
3. 完了すると履歴が選択され、地図・各タブ・シークバーで確認できます。

NMEAテキストを50 MiBまで読み込めます。元ファイルは変更せず、元データのコピーと解析済み座標を保存します。実測時刻の間隔を待たずに一括処理します。読み込み中もUSBの受信・記録は継続します。
有効なGGA位置がないファイルはエラーになり、履歴へ登録しません。
ファイルは同じPCのPythonサーバーへ送られ、外部サービスへは送信しません。
日時はログ内のRMCとGGAから取得します。履歴の登録時刻はインポートしたPC時刻です。

## 履歴を確認する

### このアプリで保存した計測

1. 「保存した履歴」から計測を選びます。
2. スライダーで表示時点を選びます。その点までの経路、座標、品質、日時を表示します。
3. 「履歴を再生」で点を順に表示します。「全軌跡・最後の点」で末尾へ戻ります。

ブラウザー版の再生は1点ごとに0.2秒で進みます。計測中の待ち時間を再現する実時間再生ではありません。

### Tera Termなどで保存したログ

ログを `data/measurement.log` に置き、次のように起動します。

```sh
uv run python -m gnss_maps.live --replay "data/measurement.log"
```

接続先で「指定したログを再生」を選び、「計測開始」を押します。GGAごとに0.2秒待ちながら読み込むため、長いログでは読み込みに時間がかかります。入力ログは変更せず、再生した内容を別の計測として保存します。

ファイルを直接開いて履歴を確認する場合は、[デスクトップ版](docs/DESKTOP.md)も利用できます。

```sh
uv run python -m gnss_maps.desktop --log "data/measurement.log"
```

デスクトップ版はTkinterの画面で、ブラウザー版とは保存先・操作が異なります。

## オフライン地図を準備する

地図画像はGitHubに同梱していません。対象範囲の画像を事前に保存します。

1. ネット接続がある場所でブラウザー版を起動します。
2. 対象地域のログをインポートするか、保存済みの履歴を選びます。デモを停止して保存した履歴でも試せます。
3. 地図タブの「全経路の地図を準備（ネット必要）」を押します。
4. 完了したらページを再読み込みし、履歴を選び直します。
5. 右上で国土地理院の地形図または航空写真を選び、経路の背景が出ることを確認します。

経路全体と周囲の余白を含む画像をズーム14〜18で取得します。
標準プリセットを置き換えるので、以前の地域も残す場合は取得前に下記2ファイルを別の場所へコピーしてください。
範囲が広すぎると取得を中止します。
この場合は地域ごとに分けたログを用意するか、[デスクトップ版](docs/DESKTOP.md)で必要な地域を準備してください。
画面の表示範囲指定は、地図取得範囲を狭める操作にはなりません。
取得時は対象範囲を含むタイルの要求を国土地理院へ送ります。

```text
data/desktop/presets/
├── std.mbtiles             # 地形図
└── seamlessphoto.mbtiles   # 航空写真
```

ブラウザー版はこの2ファイルを参照します。保存範囲外は背景が空欄になりますが、受信と記録は続けられます。高倍率では保存画像を拡大するため、画像自体の詳細は増えません。地形図は2D画像で、3D地形表示ではありません。

手元の画像MBTilesを画面から登録する操作はデスクトップ版にあります。ブラウザー版には任意ファイルの登録画面はまだありません。[地図の形式・取得手順](docs/DESKTOP.md#地図)も参照してください。

## Google航空写真を使う場合（任意）

国土地理院の地図だけを使う場合、この設定は不要です。
Google航空写真はオンライン専用で、利用者自身のGoogle Cloudプロジェクト、請求先登録、Maps JavaScript APIの有効化とAPIキーが必要です。
料金条件と設定方法は[Google航空写真の設定手順](docs/LIVE.md#google航空写真へ切り替える)を参照してください。

APIキーは `GOOGLE_MAPS_API_KEY` 環境変数から読み込みます。
ソースコードへの書き込みは不要です。
プロジェクト直下の `.env` を起動時に自動で読み込みます。
`.env.example` を `.env` にコピーし、`GOOGLE_MAPS_API_KEY=` の後ろに自分のキーを保存すると次回以降の入力は不要です。
`.env` はGitの対象外です。既存の環境変数がある場合は環境変数を優先します。
設定変更後はアプリを再起動してください。
既定のポートは8765、Google設定例では8766を使うため、Google側の許可URLを実際の起動ポートと合わせます。

APIキーはブラウザーへ渡される仕様です。
ウェブサイト制限とAPI制限を設定し、引き継ぎ先には各自のキーを作成してもらってください。
個人のキーをREADME、スクリーンショット、実行コマンドの記録などに含めて配布しないでください。

## 経路の区間指定と草刈り幅表示

「表示する時点」の下の「経路の表示範囲」で開始と終了を指定します。
両端を含む区間が地図、散布図、時系列、履歴再生に適用されます。
「全範囲に戻す」で解除できます。
通常のCSV、KML、元ログ保存は全ログが対象で、区間指定によって元ファイルを書き換えることはありません。

「草刈りの仮幅推定モード」は直径50 cmの刃と、アンテナから機体前方30 cmの位置補正を仮定した表示です。
機体方位は経路から推定するため、実際に刈れた範囲を保証しません。
専用の「草刈り幅KMLを作成（表示時点まで）」は選択区間内の表示時点までを出力します。
詳しくは[ブラウザー版ガイド](docs/LIVE.md)を参照してください。

## 実験区間の保存と位置合わせ

開始と終了を選び、「実験区間の保存と位置合わせ」で名前を付けて保存できます。
「前の点／次の点」と点番号入力で対応点を選べます。
同じ場所のFIX点と品質2の点を指定すると、選択区間だけを平行移動し、FIXの外周と比較できます。
元ログと品質は変更しません。操作と仮定は[実験区間の保存手順](docs/LIVE.md#実験1実験2として区間を保存する)を参照してください。

## 他の人への引き継ぎ

プログラムはGitHubのURLを共有してください。
計測データも渡す場合は、共有してよい位置情報かを確認したうえで、アプリを停止してから別途コピーします。

| 渡すもの | 役割 |
| --- | --- |
| GitHubのURL | ソースコードとセットアップ手順 |
| 必要な `.log` ファイル | 相手が画面からインポートして確認するための測位記録 |
| `data/live/` 全体（必要な場合） | 計測一覧も含めて保存履歴を引き継ぐためのデータ |
| `data/desktop/presets/`（必要な場合） | 取得済みの国土地理院地図。利用条件と出典表示を維持する |

受け取り側の `data/live/` に既存の履歴がある場合、上書きせず、ログのインポートで追加してください。
`.venv/`、個人のAPIキー、シェル設定ファイルは引き継ぎ対象に含めません。
GitHubから取得するだけでは、元のPCの履歴やGoogleキーは移りません。

引き継ぎ完了の確認項目：

- [ ] デモを開始して、点数が増え、生データが流れる。
- [ ] 停止後に履歴を選び、開始と終了の区間指定ができる。
- [ ] アプリを終了して再起動しても、履歴が残っている。
- [ ] 元ログを保存し、画面から再インポートできる。
- [ ] 国土地理院の地図を取得し、ネットを切っても背景と経路を表示できる。
- [ ] 実機を使う場合は、USB接続先と通信速度を確認し、短い試験計測を保存できる。

## KML・CSVに変換してGoogleマイマップで使う

```sh
uv run python -m gnss_maps "data/measurement.log" --out result --time-step 10
```

| 出力 | 内容 |
| --- | --- |
| `result/track.kml` | 経路と開始・終了地点 |
| `result/time_points.kml` | 日時付き地点。既定は10秒間隔 |
| `result/points.csv` | 全有効点の座標、UTC時刻、品質、区間 |
| `result/time_points.csv` | 日時付き地点の一覧 |
| `result/summary.json` | 点数や区間数などの集計 |

Googleマイマップで `track.kml` をインポートします。日時付きピンは `time_points.kml` を別レイヤーに読み込みます。詳しい操作と変換の仕組みは[ログ変換ガイド](docs/CONVERSION.md)にまとめています。

```text
GNSS_TEST/
├── README.md                  # 導入と基本操作
├── pyproject.toml             # Pythonの依存関係とプロジェクト設定
├── uv.lock                    # 依存関係のバージョンを固定
├── .python-version            # 使用するPython（3.12）
├── .gitignore                 # 実測データなどをGitから除外

│   ├── live.py                # ブラウザー版のUSB受信、保存、HTTP API
│   ├── mowing_heading.py      # 経路から機体方位と前後進を推定
│   ├── mowing_export.py       # 草刈り幅を統合してKMLへ出力
│   ├── web/
│   │   ├── index.html         # 画面の構造
│   │   ├── mowing.js          # ブラウザー側の方位推定と草刈り幅計算
│   │   ├── app.js             # タブ、地図、グラフ、履歴操作
│   │   ├── style.css          # 配色、配置、フォント
│   │   ├── fonts/             # IBM Plexフォントとライセンス
│   │   └── vendor/leaflet/    # 地図描画ライブラリとライセンス
│   ├── desktop.py            # Tkinter版の画面
│   ├── session.py            # Tkinter版の受信、記録、履歴解析
│   ├── offline_map.py        # MBTilesの検査とTkinter版の地図表示
│   └── presets.py            # 国土地理院画像の事前取得
├── docs/
│   ├── LIVE.md               # ブラウザー版の詳しい操作・制限
│   ├── DESKTOP.md            # デスクトップ版の操作・地図の準備
│   └── CONVERSION.md         # KML変換、NMEAの形式、座標変換
├── tests/                    # 解析、受信、切断、保存、HTTPのテスト
├── scripts/                  # Tk画面と地図描画の検証スクリプト
├── data/                     # 入力ログ、履歴、地図（.gitkeep以外はGit対象外）
├── result/                   # 変換結果（Git対象外）

```

ブラウザー版のコードは `live.py → web/index.html → web/app.js` の順に読むと、受信から表示までを追えます。座標変換を知りたい場合は `nmea.py`、日時の処理は `timed.py` を参照してください。

## 困ったとき

| 症状 | 確認・対処 |
| --- | --- |
| `uv` が認識されない | uvを導入後、ターミナルを開き直す |
| `gnss_maps` が見つからない | `pyproject.toml` のあるフォルダーで実行する |
| USBポートが出ない | データ通信対応ケーブルを確認し、抜き差しして一覧を更新する |
| ポートを開けない | Tera Termなど同じポートを使うソフトを閉じる |
| 受信中だが位置が出ない | 生データでGGAの品質と座標欄を確認する |
| 地図取得で `WinError 32`、`std.partial` と出る | アプリをCtrl+Cで終了し、最新版へ更新して再起動する。取得途中のファイルは再実行時に作り直します |
| 地図が白い／背景がない | 地図を取得済みか、表示位置が保存範囲内かを確認する |
| USBが途中で切れた | エラーを確認し、機器をつなぎ直して新しい計測を開始する |
| 保存エラーが出る | 保存先の空き容量と書き込み権限を確認する |
| ポート8765が使用中 | `uv run python -m gnss_maps.live --port 8766` で起動する |
| Tkinter版で `_tkinter` がない | [デスクトップ版の導入手順](docs/DESKTOP.md#起動)を参照する |

解決しない場合は[Issues](https://github.com/TomoakiKimura0220/GNSS_TEST/issues)にOS、操作、エラー内容を記載してください。実測ログには位置情報が含まれるため、公開する内容を確認してください。

## 検証範囲と制限

```sh
uv run python -m unittest discover -s tests -v
```

- macOS・Python 3.12で自動テスト30件が通っています。ブラウザーのタブ切り替え、デモ受信・保存、履歴シーク、地形図・航空写真の表示を確認しています。
- 2026-11-17にGit管理対象だけを別フォルダーへ展開し、macOSで新しい仮想環境への `uv sync --locked` と起動用モジュールの読み込みを確認しました。新規Windows環境での動作保証ではありません。
- JavaScriptの地図切り替え、区間選択、草刈り幅は模擬環境のテストで確認しています。Google APIキーを使った実画像の表示は、このテストには含まれません。
- Windows実機と、このアプリによるGNSS実機のUSB受信は未検証です。
- 履歴は全点を読み込みます。長い記録は読み込み時間とメモリー使用量が増えます。保存する実験区間と草刈り幅KMLは最大50,000点、生データ表示は最大1,000行です。元ログと全座標は保存します。
- 生データの履歴表示は選択UTCの最初の一致を使うため、複数日に同じUTCが出るログには制限があります。
- 時系列は有効な測位点が対象です。測位不可の品質0は生データで確認します。
- 初回セットアップ・地図の取得・外部Googleマップリンクの利用にはネット接続が必要です。

### 経路の途中で地図が途切れる場合

履歴を選び、地図の「全経路の地図を準備（ネット必要）」を押してください。経路全体と周囲の余白を国土地理院から取得し、標準プリセットを置き換えます。対象範囲が配信元に伝わります。範囲が広すぎる場合は取得を中止してエラーを表示します。詳細画像がない場所は、保存済みの粗い画像があれば拡大して補います。どの倍率にも画像がない場所は空欄です。
